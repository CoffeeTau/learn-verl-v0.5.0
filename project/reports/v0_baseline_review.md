## 已确认结果

- 数据划分：train=2000，dev=200，test=300；共享库 17361 chunks，固定背景 3000 paragraphs。
- 支持句映射：6258 条，missing=0；同名不同文本标题数 232，按不同 ID 保留。
- 索引：GPU 编码，shape=[17361,768]；数据与索引的 corpus SHA256 摘要均为 `f9993d8fd9070b21`。
- V0：200/200；单并发，max_searches=4；canonical-answer EM=39.50%（79/200），F1=49.71%。
- 平均搜索 3.12 次，总 token 4712，题耗时 1.80 秒。token 含重复 prompt，题耗时不含模型/索引初始化。
- answered=195，invalid_action_format=5（2.5%）；6 条 insufficient evidence 属于 answered 内，不是额外 6 个失败退出；2 条未知来源 ID 属于独立引用诊断。

## 问题解释

数据准备时的“序列超过 512”警告发生在 tokenizer 长度探测。`paragraph_chunks()` 先编码候选拼接以测长，超过 384 就另起片段；这一阶段没有把候选长序列送入 E5 前向。索引已成功，无需为该警告重做数据/索引。

missing=0 只说明保留样本的标注支持句在共享库中能定位，不能证明关系标注语义全部正确，也不能证明 Agent 能检索到。Rejected=0 仅统计扫描到的任务候选，无需为了制造“清洗效果”强行删题；它不代表背景段落从未因过长而跳过。

失败例的输出与 gold 均包含 Campbell 等词，部分 token 重叠会提高 F1。因此 F1 高于 EM 不能简单解释为“多数错误只差一点”。截图中的祖父问题出现围绕原实体反复改写查询，提示关系链推进可能不足；尚不能区分检索缺证据、理解错关系或标签/别名问题。以既有轨迹的支持片段覆盖和少量原文核查确认，不重跑评测。

当前分数属于项目固定小语料与所选开发子集。不能声称是官方 2Wiki 榜单表现，不能由 V0 单个系统证明多轮搜索相对单轮的独立收益，也未证明训练收益。

## 下一步决定：直接 V1 GRPO，暂不加 SFT

97.5% 的任务能产出可解析答案动作，未出现系统性格式阻塞；先不安排 SFT。5 个格式错误保留为真实失败，先读取输出，不因追求满分格式而反复调提示或放宽评分器。

V1 的接入计划（现已实现入口与本地 CPU 检查，远端运行待确认；见 `project/TRAINING.md`）：

1. 使用已冻结 train/dev 转成 veRL Parquet。prompt 只有问题和统一系统提示；答案放 reward side，标签不能进入 rollout 可见消息。
2. 将同一搜索协议迁移到 veRL 0.5.0 自定义 AgentLoop，固定现有 E5/语料/4 次搜索/非思考模式。模型动作 token mask=1，外部返回与插入模板 token mask=0。保留实际采样 token，不能直接用 V0 的重渲染对话代替训练 token 轨迹。
3. 终局奖励使用当前 canonical token F1，格式无效为 0，暂不叠加过程奖励、引用奖励或搜索成本惩罚。
4. 训练 rollout 开启采样，每题 4 条；正式评测仍保持当前确定性生成设置。开发集 39.5% 的 greedy EM 不保证训练组内有奖励差异，需从首批训练日志检查。
5. 先做 2 个真实更新步骤，确认多轮 rollout、mask、组内不同奖励、有限且非零的更新与 checkpoint 保存。它属于 V1 正确启动检查，不是额外实验线。
6. 启动检查通过后完成一次固定预算训练，再用同一 200 题开发集和相同评分规则评 V1。冻结 test 不用于调参。默认先沿用指南 8×L40S、16 题/批、n=4，具体配置必须以适配后的资源实测为准。

RE-TRAC、检索器训练和 ReSeek 纠错增强仍按原计划后置。保留本次 V0 的配置/轨迹/指标，不覆盖它。实体别名若后续补齐，应对各版本已保存答案统一重评分，而不是只修正某一版本。
