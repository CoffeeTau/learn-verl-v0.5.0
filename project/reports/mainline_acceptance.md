# Agentic Search 主干结果与阶段验收

更新：2026-10-07。依据远端截图、本地实现和保存轨迹的离线统计整理。冻结测试集四版本运行已完成；这表示评测执行完整，不代表全部答对或演示交付完成。案例见 [代表案例分析](representative_cases.md)，过程决策见 [实验日志](../EXPERIMENT_LOG.md)。

## 当前结论

主干的数据处理、V1/V2 策略训练、V3 检索适配与开发集评测均已跑通。**按开发集选择 V2 为交付候选**；V3 开发集未获整体收益，但自然测试集有质量增益，困难组退化且成本更高；作为存在取舍的增强尝试保留。停止本轮开发集调优，不用测试集继续选择超参数。

V2 相比 V0：EM +26.00 个百分点、F1 +22.48 个百分点，平均搜索 3.12→2.37。V2 仍存在 15/200 道判断—动作冲突，不能表述为已经实现可靠的证据纠错或正确的停止判断。

## 冻结测试集验收安排（执行前固定，现已完成评测）

1. 在第一次测试前固定 V0–V3 权重、检索索引、提示词、严格评分、预算和版本对应关系；V2 的候选选择已由 dev 完成。
2. 已实现独立 test 入口，运行前核对：从冻结 `test.jsonl` 与私有标签读取任务，校验文件 hash；不得把现有仅面向 dev 的命令改名就当作 test 验收。
3. 先执行同一 300 题自然任务的四版本统一验收。指南另含固定困难小子集，须在看测试成绩前固定子集和扰动规则；统一入口已在远端执行；具体命令见 [冻结测试集操作](../ACCEPTANCE.md)，实际成绩与边界见下方结果。
4. 每次保存独立 run 与全部失败轨迹，回传紧凑摘要；不因成绩不佳改提示词、选 checkpoint 或重新训练。测试时若发现明确程序错误，记录修复及重跑范围。
5. 补充最终测试表和有证据支持的代表案例，提供文本运行/回放入口。当前案例文档仅使用已回传材料，不为凑数量编造案例。

## 复盘结论

遇到困难时：先区别数据/接口错误与策略质量问题，用持久轨迹定位；状态改写导致协议全失败时恢复对话契约，而不是放宽评分。组合增强未超过基线时保留负结果，并选择已有更优版本。

再做一次：更早对齐训练与推理消息结构；检索训练更贴近真实子查询和关系混淆；状态表示在策略适配前确定。它们是合理优化方向，本项目没有通过消融证明其独立因果效果。

验收入口更新：`project.evaluation.acceptance` 自动固定四版本与困难计划，顺序执行自然300题＋困难75题并汇总；本地验证已完成，远端测试成绩已回传，见下方。

- 结论更新：V3在开发集无整体收益，但自然测试集有质量增益、困难组退化且成本较高；不再笼统称其“完全无效”。仍保留测试前由开发集选定的V2作为交付候选，不利用测试集重新选择版本或调参。
- 执行口径：本轮曾由串行切换多卡，截图无法确认哪些版本复用了串行结果。秒数保留为观测值，不用于宣称公平速度提升；实际分配见该run的execution文件。token按各版实际输入输出统计，可以比较但不是纯生成token。
