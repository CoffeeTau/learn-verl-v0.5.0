# Agentic Search 主干结果与阶段验收

更新：2026-10-07。依据远端截图、本地实现和保存轨迹的离线统计整理。本文是阶段验收记录，不代表冻结测试集已经通过。案例见 [代表案例分析](representative_cases.md)，过程决策见 [实验日志](../EXPERIMENT_LOG.md)。

## 当前结论

主干的数据处理、V1/V2 策略训练、V3 检索适配与开发集评测均已跑通。**按开发集选择 V2 为交付候选**；V3 作为一次没有获得整体收益的增强尝试保留。停止本轮开发集调优，不用测试集继续选择超参数。

V2 相比 V0：EM +26.00 个百分点、F1 +22.48 个百分点，平均搜索 3.12→2.37。V2 仍存在 15/200 道判断—动作冲突，不能表述为已经实现可靠的证据纠错或正确的停止判断。

| 指标 | V0 提示词 | V1 GRPO | V2 纠错增强 | V3 检索适配＋状态 |
|---|---:|---:|---:|---:|
| EM | 39.50% | 62.50% | **65.50%** | 62.50% |
| 正确题数 | 79 | 125 | **131** | 125 |
| token-F1 | 49.71% | 69.28% | **72.19%** | 70.14% |
| 平均搜索次数 | 3.12 | 3.31 | **2.37** | 2.50 |
| 平均 token | 4712 | 4810 | **3593** | 5626 |

所有题（包括失败）进入分母。insufficient evidence 是合法 answered 的子类，不与协议失败相加解释为总失败数。token 包含重复读取的 prompt；耗时为并发 1 的单次观测，不含模型/索引加载，不是完整部署延迟。引用指标仅诊断，不改变答案分数。

| 相邻阶段配对 | 错→对 | 对→错 | 均对 | 均错 |

| V0→V1 | 65 | 19 | 60 | 56 |

V3 的 22 道退化中，10 道因 judge/action 冲突失败、12 道合法结束但答错。两版本都 answered 的相同 169 题，V2→V3 token 3300→5421，说明高成本不只来自失败题。只减少重复查询，没有转化为总成本或质量收益。

## 数据、训练与工程验收

| 环节 | 已有证据 | 状态与边界 |
|---|---|---|
| 数据构建 | 冻结 train/dev/test=2000/200/300；问题/ID 去重；17361 chunks；6258 条支持句映射、missing=0 | 已完成；共享库含事实不等于向模型提供测试标签 |
| 划分隔离 | train/dev 来自官方 train，项目 test 来自官方 dev；全部官方 dev ID/问题排除训练候选 | 已实现；项目重建任务，不是官方榜单设置 |
| 模型与资源 | Qwen3-4B 非思考模式，原始 E5；远端资源与搜索链路通过 | 已完成 |
| V1 策略训练 | veRL 0.5.0 GRPO，8×L40S，125 步，16题×4轨迹/步；日志记录梯度和参数抽样变化，最终 checkpoint | 已通过远端截图确认 |
| V2 策略训练 | 从 V1 继续；500/2000 题计划首次困难返回，judge＋动作，用户确认正式训练 PASSED | 不把计划干预数当成实际生效数；完整训练审计未回传 |
| 奖励与 mask | 合法终局 token-F1；工具/模板 token 不参与策略损失，另用 KL loss | 不存在独立 judge 正确性奖励或已训练的 reward model |
| V3 检索训练 | 3920 组、1846 道 train 题，1正3负，单卡490步；参数变化0.00145，平均loss0.0155 | 训练通过；弱监督四选一 loss 很低不证明全库检索提高 |
| V3 状态与推理 | 修复后保留动作/返回历史，追加来源 ID、查询、未验证判断与预算；200题完整执行 | 链路恢复，但开发集无整体收益；未实现 API 压缩/完整 RE-TRAC |
| 可观测性 | JSONL、TensorBoard、完整轨迹与截图摘要 | 已使用；历史导入时间不等于真实训练耗时 |
| 最终测试与交付 | 冻结 test=300 已准备 | **待执行，不填成绩、不宣称最终验收完成** |

参考工作的定位：Search-R1 提供搜索 RL 协议与实现参考；ReSeek 启发判断和补查；Agentic-R 启发一次顺序检索适配；RE-TRAC 启发状态保留；MiroFlow 提供运行编排思路。不是五套系统的完整复现。具体复用见 [THIRD_PARTY.md](../THIRD_PARTY.md)。

## 冻结测试集验收安排（尚未执行）

1. 在第一次测试前固定 V0–V3 权重、检索索引、提示词、严格评分、预算和版本对应关系；V2 的候选选择已由 dev 完成。
2. 已实现独立 test 入口，运行前核对：从冻结 `test.jsonl` 与私有标签读取任务，校验文件 hash；不得把现有仅面向 dev 的命令改名就当作 test 验收。
3. 先执行同一 300 题自然任务的四版本统一验收。指南另含固定困难小子集，须在看测试成绩前固定子集和扰动规则；统一入口现已实现，尚未远端执行；具体命令见 [冻结测试集操作](../ACCEPTANCE.md)，取得结果前不能宣称验收完成。
4. 每次保存独立 run 与全部失败轨迹，回传紧凑摘要；不因成绩不佳改提示词、选 checkpoint 或重新训练。测试时若发现明确程序错误，记录修复及重跑范围。
5. 补充最终测试表和有证据支持的代表案例，提供文本运行/回放入口。当前案例文档仅使用已回传材料，不为凑数量编造案例。

## 复盘结论

遇到困难时：先区别数据/接口错误与策略质量问题，用持久轨迹定位；状态改写导致协议全失败时恢复对话契约，而不是放宽评分。组合增强未超过基线时保留负结果，并选择已有更优版本。

再做一次：更早对齐训练与推理消息结构；检索训练更贴近真实子查询和关系混淆；状态表示在策略适配前确定。它们是合理优化方向，本项目没有通过消融证明其独立因果效果。

验收入口更新：`project.evaluation.acceptance` 自动固定四版本与困难计划，顺序执行自然300题＋困难75题并汇总；本地39项测试通过，远端测试成绩待回传。
