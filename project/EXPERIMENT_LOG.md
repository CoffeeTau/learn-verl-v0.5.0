更新：2026-10-07。只维护主干实验的关键结果、代表性问题和决策依据；小报错、安装过程、逐次运行输出不收录。后续各阶段沿用本文件，命令与操作细节见 [TRAINING.md](TRAINING.md)。

证据来源：用户提供的远端截图与本地实现核对；没有直接读取远端完整轨迹。下文区分已观察结果与待验证解释，不补全截图截断的内容。

## 固定任务与评测口径

- 模型：Qwen3-4B，非思考模式；固定 E5-base-v2 检索器。V0 为提示词 Agent，V1 为基础 GRPO。
- 数据：2Wiki 原始格式数据，经问题/ID 去重、划分隔离、句子级切块与支持证据映射，冻结 train=2000、dev=200、test=300。官方 dev 的全部 ID/问题从训练候选中排除；项目 dev 来自官方 train。
- 共享语料：17361 chunks，背景 3000 paragraphs；6258 条支持句映射，missing=0；保留 232 个同名不同文本标题。语料 hash 摘要 `f9993d8fd9070b21`。
- 同集比较：固定 200 题 dev、top-3、最多 4 次检索、每轮最多 512 新 token、8192 上下文、确定性生成；V0/V1 统一提示词，只替换策略权重；V2 增加 judge 协议。三者沿用原始 tokenizer 和 V0 对话重渲染流程，按各自协议严格解析。
- 分数：canonical-answer EM/token-F1，无别名扩展；失败题保留在分母中。test 尚未用于评测或调参。结果属于项目重建语料与子集，不是官方榜单成绩。

## 主干结果

| 指标 | V0 提示词 Agent | V1 基础 GRPO | 变化 |
|---|---:|---:|---:|
| 开发题数 | 200 | 200 | 相同 |
| EM | 39.50%（79/200） | 62.50%（125/200） | +23.00 个百分点 |
| F1 | 49.71% | 69.28% | +19.57 个百分点 |
| 平均检索次数 | 3.12 | 3.31 | +0.19 |
| 平均 token 用量 | 4712 | 4810 | +98（约 2.1%） |
| 平均题耗时 | 1.80 秒 | 2.00 秒 | +0.20 秒 |
| 格式失败 | 5 | 3 | -2 |
| insufficient evidence | 6 | 1 | -5 |
| 未知引用 ID 的题数 | 2 | 1 | -1 |

耗时为单并发观测，不含加载；token 含重复读取的 prompt，不是纯生成 token。insufficient evidence 属于 answered 内部子类；引用错误是独立诊断，不改变答案分数。

**结论：** V1 在固定开发集上明显优于 V0，EM 净增加 46 题；这不是“恰有 46 题被修复”，逐题变化为错→对 65、对→错 19。搜索与 token 成本略增，当前未观察到效率提升。格式失败最多只涉及 V0 的 5 题，因此总体提升不能仅由格式改善解释。单次开发集结果不证明多种子稳定性、官方基准泛化或具体组件的独立贡献。

### V0：确定训练起点

97.5% 的题能给出可解析答案动作，因此直接进入 GRPO，没有为少量格式错误额外安排 SFT。离线轨迹显示：103/200 题用满 4 次检索，72/200 题出现字面完全重复查询；121 条 nonexact 中，59 条见过全部标注支持片段、60 条见过部分、2 条未见。说明优化不能只围绕检索召回，证据使用与关系推进也值得关注；标注覆盖不能直接作为错误原因标签。

### V1：基础 GRPO 是否带来收益

- 配置：8×L40S，16 题/步，每题 4 条轨迹，125 步，共 8000 条轨迹；从原始 Qwen3-4B 起步，固定检索器。
- 奖励：合法终局答案的 token-F1；格式错误、未完成/超预算、截断为 0；KL loss 系数 0.001。未增加过程奖励、检索成本/重复查询惩罚或引用奖励。
- 训练证据：125/125 步均记录有限非零梯度及抽样参数变化，最终 checkpoint 保存成功；7995 条 answered、5 条格式失败。241/2000 组（12.05%）存在奖励差异。
- 思考：多数题组同分，组内答案奖励的区分信号有限；同分可能全对、全错或相同部分分，不能直接解释为训练无效。已有开发集收益，先保留结果，不为了提高“差异组比例”立即增加采样数或重训。

## V1 离线复盘与 V2 方向（2026-10-07）

- 同题配对：错→对 65， 对→错 19，两者均对 60，两者均错 56。净增 46 与 EM 表一致；V1 有收益也有回退，不能只收集成功案例。
- V1 的 75 条 nonexact：45 条见过全部标注支持片段、28 条见过部分、2 条未见。相比 V0 的 59/60/2，各桶涉及不同题目，不能当作同一批题的因果变化。当前需关注证据使用/实体关系核对，不能只扩大检索库。
- 字面重复查询轨迹：V0 72/200 → V1 77/200；搜索效率未随答案质量一起改善。
- 历史训练组：全 1 分 1160（58%）、全 0 分 396（19.8%）、相同部分分 203（10.15%）、有差异 241（12.05%）。全 1 分不等于证据推理正确，全 0 分也不证明最终策略仍然不会答；这里只用于构造候选训练场景。
- **V2 拟采用 ReSeek 风格的证据判断与定向补查，搭配项目自建困难 episode；不是完整复现 ReSeek。** 参考仓库包含 JUDGE 和指导性过程奖励；困难 episode 是本项目的数据构造设计，不能直接称为原论文机制。
- 最小方向：普通训练题与受控困难返回混合；仅在 train 中制造一次缺关键证据/相关干扰返回，保持共享库中证据可恢复；模型明确记录“证据是否足够、还缺哪条关系”，再补查或回答。仍限制 4 次搜索，判断也计入生成 token 预算，不用强模型 API。
- 奖励先沿用终局 F1 + KL；判断字段用于行为表达，不把它的存在当作判断能力的证明，也不因输出判断标签而加分。未复用参考 regex 实现中的“最终答案字符串出现在信息中”过程标签，避免把有用的桥接证据误判为无用。
- V2 主干代码已实现，远端结果见下方 V2 同集结果，操作见 [V2.md](V2.md)。从 V1 权重继续 125 步；1500 题正常返回、500 题固定困难候选，只干预首次检索并记录实际生效次数；引入同轮 judge＋动作，判断无独立奖励。实时写 TensorBoard，每 25 步在无干预 dev 上监控，最终仍做独立同集评测。不宣称判断、困难数据或额外训练的独立贡献。

## 关键困难与复盘

| 困难 | 本次处理 | 再做一次的优化思路 |
|---|---|---|
| 下载数据不等于可训练搜索任务 | 建固定共享语料，保留支持句映射与标题变体，隔离任务划分；gold 不进入模型消息/检索返回 | 起初就同步设计任务、语料、标签与评测接口；证据“存在”与模型“找得到/用得对”分开度量。 |
| 推理对话不能直接当 RL token 轨迹 | 保留实际采样 token；外部观察与插入模板 mask=0；奖励只解析模型片段 | 尽早统一训练/推理的会话构造。本轮为公平比较保留 V0 评测方式，训练保留历史 token 与评测重渲染的差异仍存在，暂不额外扩实验。 |
| 进程成功退出不等于更新证据完整 | 梯度与参数抽样变化共同检查；每步指标在 trainer 内同步写 JSONL，避免仅依赖异步终端转发 | 一开始就提供持久指标、简短截图摘要和完整本地轨迹，便于受限服务器环境复盘。 |

## V2：纠错阶段同集结果（2026-10-07）

用户确认正式训练 PASSED；以下为远端独立 dev 评测截图。未直接读取训练完整报告或轨迹。

| 指标 | V1 | V2 | 相对 V1 |
|---|---:|---:|---:|
| EM | 62.50%（125/200） | 65.50%（131/200） | +3.00 个百分点 |
| F1 | 69.28% | 72.19% | +2.91 个百分点 |
| 平均检索次数 | 3.31 | 2.37 | -28.4% |
| 平均 token 用量 | 4810 | 3593 | -25.3% |
| 平均题耗时 | 2.00 秒 | 2.29 秒 | +14.5% |
| 协议失败 | 3 | 15（judge_action_mismatch） | +12 |
| insufficient evidence | 1 | 6 | +5 |
| 未知引用 ID 的题数 | 1 | 5 | +4 |

- 结论：准确率与检索/token 成本有改善，实际延迟没有下降。净增 6 道正确题不等于只修复 6 题；配对统计待已有轨迹复盘。不宣称统计显著性，也不归因为 ReSeek 单一机制：额外训练、困难返回、提示词与协议共同变化。
- 新困难：判断与动作冲突占 7.5%，解析器会立即终止并计 0 分；成本下降可能部分来自提前失败，需查看两版本均 answered 的同题子集成本，不能直接宣称补查更高效。
- 协议冲突可能为 sufficient 后搜索/拒答，或 insufficient 后给实质答案；当前摘要不能区分。保留严格分数，不通过放宽解析抬高成绩。
- Bad case：Transitshop/The Acid 从 V1 正确退化为 V2 空答案，三次查询后未产出被接受的答案；具体冲突以保存轨迹为准。Law Or Loyalty 的导演子女题最终答对 John Derek，但仍重复查询 Children of Lawson Harris；纠错阶段未消除所有冗余搜索。
- 再做一次：把判断与后续动作的语义约定和冲突样例尽早明确；同时记录全部题成本与正常完成同题子集成本，避免将提前失败误认为效率提升。
