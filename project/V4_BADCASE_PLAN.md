# V4 badcase解决阶段：原目标保持与证据完成度

2026-10-09；研究方案及第一轮实现，尚未启动服务器训练。暂停V5第二次检索干预提案，不将其当作目标保持的主解法。

## 问题定位

- 祖父题：旧rerender轨迹前两次检索已构成原主体的两条父子关系，随后judge换成中间人物的祖父，属于可见目标漂移；最终正确候选因judge冲突未通过。
- 生日困难题：补查找回正确歌手，却没查生日便宣称sufficient。judge仍提及生日，不能证明字面上忘记了问题；更准确的是将中间实体已知误当最终属性有据，发生证据完成度误判。
- 两者可统一为“相对原问题维护任务状态与完成条件不可靠”，不是已证明的上下文截断或同一个内部机制。第二次干预改变观察难度，不能直接监督状态转移；当前生日轨迹确实执行了第二次查询，缺的是找回歌手后的第三次查询。
- 已对齐参考：V4 step100自然80%、困难62%，自然→困难11退化全answered。旧案例属于rerender，不假定在新路径仍失败，实施前只读新路径对应案例及少量实际退化；不追加完整诊断推理或用开发题训练。

## 参考核查与可借鉴边界

1. ReSeek论文把有用中间实体与足以作答区分；其引言“作品创作者→生日”例与本题高度相似。论文采用判断过程监督；本地reseek_regex.py存在最终答对+Yes直接奖励及gold答案在观察中的匹配近似。这些不能当成多跳全链条完成度的可靠标签。本项目当前只有严格终局F1，不是完整ReSeek奖励复现。
   - https://arxiv.org/html/2510.00568v1
   - 本地 `project_resource/ReSeek/verl/utils/reward_score/reseek_regex.py`
2. RE-TRAC将事实/来源、结论及未解决问题组织为状态，跨轨迹传递；小模型采用对应SFT，不是简单附加长摘要。我们只有4次检索，本轮借鉴状态结构，不实现跨轨迹递归压缩。
   - https://arxiv.org/html/2602.02486v1
   - 本地 `project_resource/InfoAgent/retrac/retrac/graph.py`
3. Self-RAG区分相关性、对生成内容的支持及用途，并通过训练学习反思标记；不是只输出自评就自然可信。
   - https://selfrag.github.io/
4. Sufficient Context区分证据不足时作答与证据充分仍失败，支持将“找没找到”和“正确利用/判断”分开分析；其结果不能换算成本项目成功概率。
   - https://arxiv.org/abs/2411.06037
5. Agentic-R重点在检索效用与Agent/Retriever迭代，本例祖父必要证据已到达，不优先继续训练E5。
   - 本地 `project_resource/Agentic-R/README.md`

## 推荐主方向

不可变原问题 + 简短、带来源的关系进度 + 学习何时搜索/结束。

- 外部程序保存并按回合重申原问题原文；原主体/目标由问题解析产生时仍可能解析错，不能称为可靠真值。禁止将查询人物自动覆盖原始目标。原问题以外的分解是可修正假设。
- 模型维护少量“待回答关系→目前值→证据ID和原句→待确认项”，按原问题更新；事实与模型推断分开。已知中间人物不代表最终属性已知，两个父子关系可以组合成祖父关系，不要求祖父另有独立条目。
- 代码可验证来源ID存在、原句来自已观察证据、不可变原问题未改；不能靠字符串规则证明语义蕴含，也不能因模型填了complete就直接放行。
- 第一步只做紧凑目标提醒和结构化judge的低成本可行性检查，固定step100、检索器和token续接。避免新增庞大JSON状态、独立judge模型或强制额外搜索；仍保留原始证据。出现新格式须同训练/推理一致，不静默放宽旧评分。
- 若需让4B模型稳定使用状态，优先小规模、可核验的train-only状态→下一动作SFT，再视结果接回GRPO。SFT用于示范“缺属性就查属性、链条齐全就答、相似实体不自动合并”，不是笼统给模型更多困难题。不得直接用未验证的自评当监督或密集奖励。

## 数据质量与执行次序

1. 只读aligned已保存案例，确认当前残留问题；两道旧案例只作诊断，不作为成功验收的全部。
2. 从train内部划分训练与小型诊断题，先按题ID隔离。使用已有关系三元组和support句辅助制作局部状态，但“标题匹配+出现object”只是弱监督，须验证关系方向/实体限定词与原句一致。
3. 每类构造配对状态：仅中间实体有据、完整链有据、相似实体混淆/无关证据。负例须检查整个可见上下文，不能因缺一个gold chunk就标不足；替代证据或标注不确定的样本剔除，不把标签/未见事实放入模型输入。
4. 先筛查固定模型在这些train诊断状态上的正确下一动作、来源支持及新增格式错误。只加提醒若不能改善，不盲目放大训练；审核后的SFT示例也先做小规模验证，不提前承诺样本量或收益。
5. 全开发集确认时保留自然200/困难50、所有失败分母、成本与拒答统计；新方案不以拒答替代正确率，不用额外隐藏模型调用掩盖成本。若未获得整体收益保留V4原checkpoint和负结果。

## 与V3的区别及成功预期

V3 state_messages保存queries_seen、未验证旧judge和evidence_ids，并重建历史；没有显式已完成/缺失关系，且冻结策略未经状态训练。V3同时更换检索器与输入，其退化不能单独证明状态无效，也不能成为再堆一份ledger的理由。

代码固定原问题字段可确定阻止字段被覆盖，但无法保证模型注意或正确推理。提示单独带来稳定收益的信心有限；带可靠监督的状态跟踪/停止判断更有针对性，仍有错误状态固化、过度拒答、格式负担和SFT遗忘风险。现有论文没有本项目配置的成功概率，不能声称70%或90%能work。以小规模筛查→一次全开发确认获得本项目证据，不开展大矩阵。

已实现 `v4-base`：先用共享原目标提醒与紧凑judge，在V4 step100上做原有GRPO的受控可行性训练，保留step0和严格评分；没有新增第二次干预，也没有将弱标签当作SFT数据。状态→动作SFT仍待可靠数据审核，不能称为已完成。服务器先检查aligned保存案例及2步smoke，再决定正式125更新。操作与验收见 [V4_BASE_RUNBOOK.md](V4_BASE_RUNBOOK.md)。
