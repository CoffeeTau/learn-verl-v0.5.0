# V4：固定适配检索器后的策略再训练

状态：远端正式125步训练已通过（`main_20261007T095646Z_3f4cdb`），选中step100，待独立开发评测。操作见 [V4.md](V4.md)。文本演示与回放暂缓。

## 目标与依据

让策略适应 V3 E5 的返回分布，在普通检索和首次证据受扰时，学会有效补查与合法终止。V3 同时改变检索器与状态输入，却冻结了 V2 策略；开发集协议冲突20/200、token5626，说明值得先解决协同与输入复杂度，而非继续单独降低 E5 训练 loss。失配是待验证解释，不是已证实原因。

借鉴 Agentic-R 的 Agent/Retriever 交替优化思路，只做一次“固定新检索器、更新 Agent”；不复现其 local/global utility、强模型子答案或完整迭代。保留项目已有 ReSeek 风格 judge/补查，困难返回是本项目设计。参考 ReSeek 的 reseek_regex 奖励涉及答案字符串重叠，不直接用作多跳证据充分性标签。RE-TRAC 的跨轨迹压缩暂缓，现有 V3 ledger 也不等于 RE-TRAC。

## 固定方案

| 项目 | V4 决策 |
|---|---|
| 策略初始化 | V2 最终 Qwen 权重；V3 没有独立训练的 Qwen 权重 |
| 检索环境 | 冻结 V3 E5 及其已有索引，不重训、不重建 |
| 输入 | 沿用 V2 system/历史/judge 协议，移除 V3 附加 ledger 和提示；这是有意简化，不能把结果只归因于新增训练 |
| 数据 | 冻结 train2000；沿用1500自然＋500首次检索干预候选，同题4条采样使用同一干预规则；记录实际生效 |
| 数据逻辑 | 只改首次返回，后续恢复，标签不进入模型输入；不按 test 案例选样，不扩数据或重采样历史失败题 |
| 奖励 | 合法完整轨迹的终局 canonical F1，否则0；KL loss 0.001，reference 固定为初始 V2 |
| 资源 | 8卡，16题/步×4采样，学习率1e-6，125步上限，最大4次检索、top3、每轮512新token；沿用已跑通预算 |
| 额外机制 | 不增加答案重叠过程奖励、搜索惩罚、强模型API或在线检索器更新 |

协议正确本来就是获得终局奖励的条件，不额外奖励输出 sufficient 或 judge 标签，避免形式满足替代实际答题。不把支持片段未齐等同于证据必然不足；覆盖仅作诊断。

## 执行顺序与监控

1. 实现独立 V4 配置、检索器/索引来源校验、训练入口与评测入口；保留 V0–V3 产物。训练续接复用现有模型 token 保留及外部观察 mask=0 机制。
2. 2步8卡 smoke 验证采样、奖励、梯度、参数变化、保存与恢复所需产物。只验证接入，不据 smoke 声称质量改善。
3. 正式运行125步。step0 与每25步在相同 dev200 上做自然评测；另外固定其中50题的首次干预评测，并输出这同一50题的自然成绩。扰动标签只由环境读取，checkpoint 间规则不变。
4. TensorBoard 每步记录 reward、EM/F1、协议失败率、搜索/token、组内奖励差异比例；每25步更新开发集自然/干预曲线。区分训练批次趋势与固定开发集质量。
5. 保存按下述开发规则选出的 best checkpoint 和最终 checkpoint；需调整现有仅保留最后2个 checkpoint 的策略，防止 best 被清理。最终导出 best 并做一次独立 dev 评测。

训练前的 step0 是“V2策略＋V3检索器＋V2输入”的同环境起点；用于判断本轮训练带来的变化，不等于旧 V2 或旧 V3。对旧版本仅报告组合系统差异，不声称组件独立贡献。

## 预先确定的选择与停止规则

开发集自然 EM 为主指标，EM 并列按 F1，再按较低 token 选择。候选还必须满足：协议失败数不高于 step0、固定干预50题的 EM 不低于 step0。无候选满足则不升级，保留 V2 交付候选。50题分辨率为2个百分点，只是开发约束，不是显著性证明。

本轮达到125步即停；出现非有限数或运行错误则停止排查。不为追求某条曲线临时延长训练，不开展多参数网格。效果不佳时优先用 train/dev 既有轨迹分析一次，再决定是否需要独立的奖励/数据改进。

旧 test300 已公开且结果已参与后续讨论，不能再当 V4 全新盲测。旧 test 仅可标注为历史回归集；V4 后续独立验收需先从未评测、无训练问题重叠的官方 dev 剩余题中冻结新集合，并保持问题标签与训练隔离。若需补充检索语料，必须为对照与 V4 同步固定新索引，不能无声改变旧基线条件；此项单独规划，本轮先完成开发集训练。

## 计划产物

采用 `runtime/runs/v4/<run_id>/`：config、manifest、metrics.jsonl、train.log、checkpoints、简短 summary；`runtime/runs/v4_eval/<run_id>/` 保存最终开发评测及轨迹；TensorBoard 位于 `runtime/tensorboard/v4_<run_id>/`。正式运行保留25/50/75/100/125五个完整 checkpoint，best由selection.json指向，step0胜出时复用初始权重；不会删除旧版本产物。
