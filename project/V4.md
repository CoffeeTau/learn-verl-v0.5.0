# V4 运行说明

目标：固定 V3 检索器，从 V2 Qwen 继续 GRPO，使用 V2 对话/judge 协议，不附加 V3 状态。设计与选择规则见 [V4_PLAN.md](V4_PLAN.md)。本地检查不代替远端 GPU 接入验证。

## 1. 更新代码后先做八卡 smoke

服务器项目根目录运行：

```bash
cd /home/h50061831/learn-verl-v0.5.0
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 bash project/scripts/run.sh \
  bash project/scripts/mainline.sh v4 --mode smoke --gpus 8
```

默认从 V2 `main_20261006T164842Z_548d39` 初始化，使用 V3 E5 `main_20261007T042356Z_357492` 的 `model/` 和 `index/`；启动会校验数据、模型库存与索引哈希。可用 `--init-run`、`--retriever-run` 明确指定其他已完成运行。无需修改 .env 中原始 E5 路径，不会覆盖原始索引。

smoke 为2次更新，每步16题×4条轨迹；step0和step2各评测8题自然＋其中2题干预，只用于接入验证。初始化和验证期间没有新的更新数字是正常的。

请返回 `runtime/runs/v4/latest_summary.txt` 一张截图。应有 `PASSED`、2/2更新、梯度与参数变化、干预生效记录、最终 checkpoint，以及选中step的信息。smoke选中step0不表示接入失败。

如失败，先截图末尾简短错误；完整日志路径为 `runtime/runs/v4/<本次run_id>/train.log`。不要为同一错误反复启动正式训练。

## 2. smoke 通过后正式训练

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3,4,5,6,7 bash project/scripts/run.sh \
  bash project/scripts/mainline.sh v4 --mode main --gpus 8
```

从初始 V2 权重重新开始，不继承 smoke 的更新。125步，train2000；step0和每25步评测200题自然＋固定50题干预，额外输出这同一50题的自然成绩。保持全部失败题在分母中；自然和干预走不同 agent registry 和环境计划，不靠temperature判断数据用途。

保留25/50/75/100/125五个完整 checkpoint（含优化器），比以前最后2个占用更多磁盘。记录按自然EM、F1、较低token优先选出的step，同时限制自然失败数和干预EM不劣于step0。若选中0，表示没有超过同环境初始模型的合格候选，不会冒充训练增益。没有自动延长训练，也没有自动恢复旧进程的命令。

完成后返回 `runtime/runs/v4/latest_summary.txt`；需要中途查看开发集时，截图 `runtime/runs/v4/<run_id>/validation_summary.txt`。

## 3. TensorBoard

若已有 TensorBoard 指向 `runtime/tensorboard`，保持运行并选择新 `v4_main_...` run即可。否则远端启动：

```bash
bash project/scripts/run.sh python3 -m tensorboard.main \
  --logdir runtime/tensorboard --host 127.0.0.1 --port 6006
```

VS Code Remote SSH 的“端口”面板转发6006，在本地浏览器打开。只读 TensorBoard event 文件；JSONL是独立持久日志，无需额外转换进程。

| 曲线 | 更新频率 |
|---|---|
| `critic/score/mean`、`train/answer_f1`、`train/answer_em` | 每个完成的训练step |
| `train/protocol_failure_rate`、`train/varying_group_fraction` | 每个训练step |
| `train/searches`、`train/total_tokens` | 每个训练step |
| `dev/natural/em`、`dev/natural/f1`、`dev/natural/protocol_failures` | step0及每25步 |
| `dev/natural_matched/em`、`dev/hard/em`、`dev/hard/f1` | step0及每25步 |
| `dev/selected_step` | 每次开发评测 |

EM/F1曲线为0–1比例。total_tokens计入多轮重复读取历史，不是纯输出token；训练失败率包括未完成、截断和协议错误。训练批次不同，reward波动不能替代固定开发集判断。

## 4. 正式训练完成后的独立开发评测

把下面的 `MAIN_RUN_ID` 替换为正式训练摘要中的run值：

```bash
CUDA_VISIBLE_DEVICES=0 bash project/scripts/run.sh \
  bash project/scripts/mainline.sh v4-eval --train-run MAIN_RUN_ID
```

自动导出选定checkpoint，评测自然200题与同一干预50题；step0胜出则复用初始V2权重。此入口单卡执行，每题协议不变；不调用冻结测试集。返回 `runtime/runs/v4_eval/latest_summary.txt` 截图。

训练中验证使用保留采样token的续接方式；独立评测沿用V0–V3对话重渲染方式，结果不保证逐字相同。该差异明确保留，避免把训练内指标直接当作最终同集成绩。

## 产物位置

- `runtime/runs/v4/<run_id>/manifest.json`：模型、数据、索引、代码来源。
- 同目录 `metrics.jsonl`、`validation_metrics.jsonl`、`selection.json`：训练曲线、各组开发指标、选模记录。
- 同目录 `validation/<step>.jsonl`：开发输出与任务ID；`reward_audit/`：训练及验证模型输出。
- 同目录 `retrieval_audit.jsonl` / `dev_retrieval_audit.jsonl`：训练/开发首次返回干预记录，分开保存。
- 同目录 `checkpoints/`：分布式权重；独立评测时生成 `hf_step_<选中步>/`。
- `runtime/runs/v4_eval/<run_id>/{natural,hard}.jsonl`：独立开发轨迹；`report.json`和`summary.txt`：结果。

V4只有train/dev优化；旧测试结果作为历史记录保存。新一轮盲测另行冻结，不能重用已讨论的旧test冒充新验证。
