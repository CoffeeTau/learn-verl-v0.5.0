# V2：证据判断与补查主干

状态：代码与本地 CPU 检查完成，远端 V2 训练尚未验证。V1 的 EM=62.50%、F1=69.28% 是基线，不是 V2 的预期保证。

## 固定设计

- 起点：V1 `main_20261006T090840Z_c41e35` 的最终 step 125 权重。新建优化器，KL 参考策略也为该 V1 权重；不是恢复 V1 optimizer，也不续接 smoke。
- 一轮：2000 道原训练题，16 题/步、每题 4 条、125 步，8×L40S。保持 F1 终局奖励、KL=0.001、每轮最多 512 新 token、上下文 8192、最多 4 次搜索。
- 1500 题保持正常返回，固定种子按 ID 哈希选择 500 题作为困难场景候选：250 题尝试移除一个标注支持段落的命中；250 题从原 E5 top-20 中排除标注支持段落后取 top-3，作为相关干扰候选。只干预首次检索；后续完全恢复正常检索。
- 不修改库、不编造文档、不注入 gold 到消息；支持段落映射仅由训练环境使用。移除一个段落时可能少于 3 条甚至为空；未命中被排除段落时可能没有实际变化。替代证据仍可能存在，不能把剩余文档都标成“无用”。实际变化单独审计，不虚报为 500 条已生效困难题。
- 选择依据是可控的数据场景，不把 V1 历史 all-zero 组当作最终模型永久不会的题。混合普通题是为了保留一般问答能力，而不是只追逐失败样本。

## 判断协议

第一次搜索沿用 `<search>...</search>`。每次收到工具返回后，模型在同一次生成中输出：

```text
<judge>insufficient: school found but founder birthplace still missing</judge><search>Example School founder birthplace</search>
```

或：

```text
<judge>sufficient: founder and birthplace supported by retrieved evidence</judge><sources>p1,p2</sources><answer>Paris</answer>
```

判断理由最多 40 个空格分词。`sufficient` 指足以回答整个问题，不等于片段有用。判断后必须同轮搜索或回答；证据不足时可以补查，停止时只能回答 `insufficient evidence`。判断不增加独立生成轮数，计入 512 token 上限。

格式/判断与动作不一致时终局奖励为 0；合法判断本身不加分。模型生成的判断、查询、答案均 mask=1，观察与外部插入模板 mask=0。仅能检验格式自洽，不能凭此证明判断内容正确。未照搬 ReSeek 的答案字符串重叠过程奖励，也未新增强模型调用。

## 实时 TensorBoard

现有 TensorBoard 服务仍指向 `runtime/tensorboard`，不用重新导入 JSONL。V2 训练直接写入：

```text
runtime/tensorboard/v2_main_<时间>_<ID>/events.out.tfevents.*
```

如服务已关闭，另开终端：

```bash
bash project/scripts/run.sh bash project/scripts/tensorboard.sh
```

沿用 VS Code Remote SSH 的 6006 端口转发，在网页选中新增 `v2_main_...` run。写入端每步 flush，页面启用自动刷新或手动刷新；只有新步骤/评测完成时才会出现新点。

| TensorBoard tag | 含义 |
|---|---|
| `critic/score/mean` | 每步平均终局 F1，0–1；V1 历史导入中也有此原始 tag，可叠加看 |
| `actor/grad_norm` / `actor/kl_loss` | 梯度与 KL 正则指标 |
| `timing_s/step` | 每步耗时 |
| `val-core/agentic_2wiki/reward/mean@1` | 在线 dev F1，0–1 |
| `val-aux/agentic_2wiki/em/mean@1` | 在线 dev EM，0–1 |

在线 dev 使用训练 AgentLoop 的 token 保留方式和 V2 判断协议；step 0 是“V1 权重＋V2 协议”的起始表现，不能直接冒充之前的 V1 正式评测分数。已有 `eval/em_percent` 是独立评测百分制，不能把它与这些 0–1 曲线混在同一尺度解释。
