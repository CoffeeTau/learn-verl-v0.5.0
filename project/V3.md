# V3：一次检索器适配与结构化证据状态

当前实现已完成本地 CPU 检查，尚未在远端训练或评测。冻结 V2 Qwen 权重，不增加第三轮 GRPO。运行顺序为：准备检索对 → E5 训练一次 → 重建独立索引 → 同集 V3 评测。所有命令在服务器项目根目录执行。

## 设计与边界

**检索数据为什么这样构造：** 祖父案例说明姓名相近不能代替关系证据。本阶段用 train 的 `evidences` 三元组构造“主体＋关系”查询，输入仍为 `原问题 [SEP] 当前查询`。正例必须是标注 supporting sentence 所在片段，标题与主体规范化后完全一致，并且支持句含关系客体；对不可靠的别名对齐直接跳过。最多固定种子选择 4000 对，不用 dev/test 标签。标准关系只用于训练，推理仍由 Qwen 生成查询。

原 E5 top-100 中筛选 3 个负例：排除该题所有支持段落、含主体或客体的片段。不能因为片段不是 gold 就直接判负。本规则保守，会漏掉更难的同主体不同关系负例，也不能排除所有别名/等价证据，因此称为规则过滤的弱监督。`pair_examples.json` 留存 5 对完整文本供复核，终端只显示 2 对标题摘要。训练只做每题 1 正 3 负的交叉熵，不使用跨题 in-batch negatives，避免同一支持文档被其他题误标为负。

**训练：** 共享 E5 query/passage encoder，全参数更新；masked mean pooling、归一化、query/passage 前缀与原实现相同。固定 1 epoch、batch=8、lr=1e-5、temperature=0.02、weight decay=0、seed=42。沿用当前环境，单张 L40S；完成后验证有限损失/梯度与抽样参数变化。只做一次，不因训练 loss 波动追加调参。

这是 Agentic-R 启发的顺序检索优化，不使用其强模型 sub-answer、local/global utility、RankNet 或交替训练，也不宣称完整复现。

**状态：** 当前先实现无需 API 的证据原文状态，字段包括已查查询/返回 ID、历史 judge（明确标为未验证）、剩余预算、按 ID 去重的完整证据文本。保留 V2 的 assistant 动作和 user 工具返回顺序，仅在最新返回后追加状态；同 ID 原文若变化则报错，不按标题合并不同人物、不把模型判断写成确定事实、不删掉旧证据。不增加模型调用或 search 配额。Qwen 仍负责判断和下一步查询；状态整理本身是确定性程序，不是额外的本地摘要模型。

这只是 RE-TRAC 启发的状态保留，不是其跨轨迹压缩/再次探索。此前讨论的 API 压缩尚未接入，待确定接口与预算后再决定是否启用；本轮无需密钥。当前版本可以独立跑通，但不能在报告里写成已实现 API 压缩或完整 RE-TRAC。

**协议：** 保持 V2 严格 judge/action 约束，提示词补充人物身份、关系方向、证据来源和终局预算规则。不会自动把 insufficient 改成 sufficient，也不会接受矛盾答案。能否改善 15 道冲突由评测决定，不能预先承诺。

回传 `=== V3 E5 TRAIN | PASSED ===` 截图。结果路径：

## 4. 同一 200 题 V3 评测

```bash
CUDA_VISIBLE_DEVICES=0 bash project/scripts/run.sh \
  bash project/scripts/mainline.sh v3-eval
```

默认冻结 `dev_20261007T024032Z_0bed4f` 使用的 V2 权重，自动读取最近成功 E5 run。可用 `--retriever-run main_<时间>_<ID>` 显式固定。最多 4 搜索、每轮 512 新 token、8192 上下文、top-3、同 tokenizer、相同评分。超长照常报 context budget，不偷偷扩大预算。token 计入每轮整个状态/证据的读取，耗时包含状态整理；没有 API 调用成本。

回传 `runtime/runs/v3_eval/latest_summary.txt` 的截图，或终端 `=== V3 DEV | ... ===`。结果比较 V0 与 V2；V3 同时改变检索器、提示词和状态组织，只报告组合效果。冻结 test 本轮不运行。
